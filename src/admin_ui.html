Step two · automatic

Finding your ONT

The proxy scans your network for the ONT, logs in, and reads the serial and TR-069 password off it — even when it's bridged. You usually type nothing here; if it can't find the device, you can point it at the address yourself.

Confirm · or fill in

Device identity

If discovery worked, these are already handled — leave them blank and the proxy reads them live each run. Fill them only to override, or if you skipped the ONT step.

Without the ONT: from a config backup — openssl aes-128-cbc -d -md sha256 -pass pass:"BE F2 …" -in backup.enc then grep ManagementServer.Password.

Run it ›

            
# build + run (amd64; use Dockerfile.arm64 for ARM)
docker build --platform linux/amd64 -t jiofiber-sip-proxy .
docker run --rm --network host --env-file ./sip.env jiofiber-sip-proxy

            
--network host lets the container source traffic from your line's real addresses. You should see Registered with upstream SIP proxy on success.

          

          
Point your phone ›

            
  • SIP server / proxy: the advertise IP + SIP port, transport UDP.
  • Codec: PCMU (G.711 µ-law) first.
  • Login: any username/password works.

            Ten-digit Indian numbers are rewritten to +91 automatically.
          

          
Troubleshooting ›

            
  • CCS request failed / reset: source address not in your /64, or Jio throttling — wait and retry.
  • Provisioning fails: re-check serial / TR-069 password, or that the ONT is reachable.
  • No / one-way audio: set the phone to PCMU; advertise IP reachable; RTP not firewalled.
  • Phone registers, ONT line drops: expected — last writer wins. Keep "disable the ONT's SIP" on.
